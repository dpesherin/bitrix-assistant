## [Unreleased]

### Подсказки

- Встроенные типы PHP (`string`, `int`, `float`, `bool`, `array`, `callable`, `mixed`,
  `self`, `static`, `parent` и остальные) подсказываются в позиции типа: тип возврата,
  тип параметра, тип свойства, типизированная константа. Поддержаны `?`, union `|`,
  intersection `&` и сигнатуры, разбитые на несколько строк. Раньше на `: str`
  предлагались функции (`strlen`) и классы, а `string` не появлялся.
- Классы тоже подсказываются в позиции типа возврата — одиночное `:` больше не
  блокирует список, как это делал `::`.
- Чейнинг с переносами строк больше не ломает подсказки: `$service` + `->` на новой
  строке, `\Demo\Helper` + `::` на новой строке, `BX.Main` + `.` в JS.
- `self::`, `static::`, `parent::` работают даже для класса, которого ещё нет в индексе
  (новый файл, untitled): свои методы берутся из документа, унаследованные — из индекса.
- `public func` подсказывает объявление функции, `private const` — константы.
- Проверено и закреплено в `npm run test:e2e`: наследование до 5 уровней, несколько
  интерфейсов сразу, трейты, переопределение (hover, definition и signature help
  отдают метод ближайшего предка). Для ещё не проиндексированного класса
  `self::` показывает собственные методы документа и предка из индекса.

### Производительность

- Индексация перестала занимать интерфейс и стала заметно быстрее. Разбор PHP и JS
  теперь идёт в потоках (до 4, на один меньше числа ядер), а основной поток только
  пишет результат в базу: полная перестройка на стенде (6 000 PHP + 1 600 JS файлов,
  40 000 методов) ускорилась с 2,2 с до 0,63 с, а самое долгое замирание интерфейса
  сократилось с 599 мс до 30 мс. Стартовая сверка индекса — со 338 до ~100 мс. На
  площадке в 36 тыс. файлов перестройка занимает ~2,8 с без замираний дольше 40 мс
  (раньше такие проекты замирали на полсекунды-секунду).
- Обход каталогов больше не читает каждый каталог по три раза, стабы PHP не
  импортируются заново на каждом обновлении, проверка «файл не менялся» идёт пулом,
  а пачка файлов пишется одной транзакцией вместо транзакции на файл.
- Новая настройка `bitrix.index.threads`: `0` — автоматически, `1` — вообще без
  потоков (если нужно минимально нагружать систему).
- Для повторяемых замеров добавлен стенд: `npm run bench:index`.

### Добавлено

- Конфликт версий при загрузке теперь можно **слить**, а не только перезаписать. Если на
  сервере файл новее и отличается, в окне загрузки появляется «Слить вручную»: открывается
  редактор слияния VS Code — слева локальная версия, справа серверная, снизу результат.
  Куски принимаются по отдельности, как в git, а после «Complete Merge» файл предлагается
  загрузить на сервер. Для каталога — «Слить по одному» и выбор файла из списка конфликтов.
  Отключается настройкой `bitrix.ssh.mergeEditor`.
- Слияние трёхстороннее, а не «слепое»: расширение запоминает последнюю синхронизированную
  версию файла (в этот момент локальная и серверная совпадают), поэтому правки в разных
  местах файла склеиваются автоматически, а конфликтом помечается только реальное
  пересечение. Снимки ограничены (256 КБ на файл, 50 МБ всего, 30 дней) и вычищаются
  в фоне — диск не растёт бесконечно.
## [0.5.5]

### Добавлено

- Открывающие теги PHP подсказываются по мере набора: `<`, `<?`, `<?=`, `<php`.
  При выборе вставляется готовый тег с закрывающим `?>` — `<?php … ?>`,
  `<?= … ?>` или `<? … ?>`. В HTML-разметке шаблона этих подсказок раньше не было.
- Enum: после `Status::` подсказываются значения (`Active`, `Blocked`), а после
  `$status->` — встроенные `name` и `value` (у backed-enum). Тип переменной
  выводится и из присваивания `$status = Status::Active`.
- `return`, `break`, `continue` подсказываются готовыми инструкциями:
  `return ▮;`, `break;`, `continue;`.

### Исправлено

- В HTML-разметке шаблона наведение и переход по `class`, `for` и другим
  атрибутам больше не показывают подсказки и объявления PHP.
- В пустом `untitled` язык переключается на PHP уже на `<?` или `<php`,
  а не только после полного `<?php` — подсказки появляются раньше.

## [0.5.4]

### Исправлено

- В HTML-разметке PHP-шаблона больше нет подсказок PHP. Раньше на `class="Test"`,
  `id="box"` и обычные слова внутри тегов всплывали классы Битрикса (с автодобавлением
  `use`), функции и константы. Теперь подсказки появляются только внутри `<?php … ?>`
  и `<?= … ?>`, а в разметке не мешают писать атрибуты.

## [0.5.3]

### Добавлено

- Конструкции языка PHP теперь подсказываются готовыми: `if`, `foreach`, `switch`, `try`,
  `match` и другие вставляются вместе с фигурными скобками и полями для подстановки.
  Раньше в списке были только функции и переменные, и конструкцию приходилось писать
  руками. Подсказки появляются в начале инструкции и не мешают внутри выражения.
- JS: подсказки и подписи параметров для стандартных объектов и функций —
  `JSON.stringify`, `Math.max`, `console.log`, `Object.keys`, `parseInt`, `setTimeout`
  и других. Раньше эти имена просто не находились.
- JS: методы прямо на значениях — `'строка'.replace(...)`, `[...].map(...)`,
  `42.toFixed(...)` — и на результате DOM-вызова: после `document.querySelector('.x')`
  подсказываются методы элемента, а не документа.
- JS: подписи параметров у функций из того же файла — `function show(...)` и стрелочных
  `const show = (...) => …`. Раньше они не показывались вовсе: такие функции не попадают
  в общий индекс.
- JS: работа с DOM и jQuery. После `const overlay = document.createElement('div')`
  подсказываются методы элемента, а `overlay.setAttribute(` показывает параметры;
  то же для `document.querySelector(...)`, `document.body` и `$('.x')`. Раньше такие
  переменные были «неизвестным объектом», и подсказок не было совсем.

- JS: имена параметров прямо в вызове (inlay hints), как в PHP:
  `overlay.setAttribute(name: 'role', value: 'alertdialog')`. Раньше для JS таких
  подстановок не было вовсе — сервер отдавал пустой список на любой не-PHP файл.

### Исправлено

- JS: стандартные функции не находились, потому что подсказки знали только индекс
  проекта. Теперь встроенные имена участвуют в общем списке, а сигнатуры параметров
  показываются при наборе аргументов.
- Цепочка запросов к Битриксу снова проходит до конца. У части таблиц первый шаг
  возвращает служебный класс, объявленный в файле модуля, который не попадал в
  индекс, — продолжение становилось неизвестным. Теперь такие файлы индексируются,
  и после обновления индекс пересобирается сам.

## [0.5.2]

### Исправлено

- Подсказки в цепочках запросов к Битриксу (`ContactCompanyTable::query()->setSelect([...])->where(...)`)
  снова идут до конца. Раньше список обрывался уже на втором шаге: часть служебных
  классов, которые ядро объявляет одним большим файлом, попадала в индекс под чужим
  именем, и продолжение цепочки становилось неизвестным. Теперь такие классы
  находятся, а `setSelect()`, `where()` и `fetchAll()` подсказываются как обычно.
- Методы, которые возвращают «тот же объект» (`@return $this`, `@method $this where(...)`),
  больше не обрывают цепочку: тип получателя сохраняется на каждом шаге.
- Цепочка, записанная в несколько строк (каждый `->` с новой строки), больше не теряет
  начало — подсказки работают и в таком стиле.
- После обновления индекс пересобирается сам: вручную чистить ничего не нужно.

## [0.5.1]

### Исправлено

- Переподключение к серверу больше не бесконечное: на попытки отводится 20 секунд от
  первого обрыва. Раньше статус-бар мог вечно показывать «переподключение…», а на
  каждую операцию уходил новый SSH-хендшейк. Теперь по истечении окна сервер
  считается невыбранным — статус-бар говорит «сервер не выбран», команды загрузки и
  скачивания скрываются, в уведомлении есть кнопка «Выбрать сервер». Дальше только
  явный выбор.
- Неудачное подключение вручную ведёт себя так же: одно сообщение об ошибке, сервер не
  выбран, в фоне ничего не повторяется.

## [0.5.0]

### Добавлено

- Видно, сколько уже перенесено: для файла — проценты и байты (`10.4 КБ / 250 КБ`), для
  каталога — `12 из 340 файлов · 3.4 МБ / 12.1 МБ (28%)` с полосой прогресса.
- Настройка `bitrix.ssh.concurrency` — сколько файлов переносить одновременно (по
  умолчанию 4, максимум 16).

### Изменено

- Каталог загружается и скачивается параллельно, а не по одному файлу; проверка
  «не перезапишу ли чужие изменения» тоже идёт параллельно. Папки на сервере создаются
  один раз за операцию, а не проверяются перед каждым файлом. На проекте из множества
  мелких файлов это убирает основную часть ожидания.

### Исправлено

- Статус-бар больше не мигает «сервер не выбран» при каждой загрузке. Раньше любая
  ошибка файловой операции — нет файла, нет прав, не удалось переименовать — считалась
  обрывом связи: соединение закрывалось и поднималось заново. Теперь переподключение
  происходит только при реальном обрыве, а сессию, которую закрыл сервер по таймауту,
  расширение поднимает в фоне и показывает `‹сервер›: переподключение…` вместо
  «сервер не выбран».

## [0.4.11]

### Изменено

- Резервные копии `.bak` больше не создаются: ни на сервере при загрузке, ни локально
  при скачивании. Вместо этого файл пишется во временный и подменяет цель одним шагом
  (а на старых серверах — с откатом), чтобы при обрыве не оставалось полузаписанного
  файла. Правила исключения для `**/*.bak` остались: старые бэкапы по-прежнему не
  уезжают на сервер.

## [0.4.10]

### Исправлено

- «Загрузить файл на сервер» для папки из проводника падало с ошибкой `EISDIR`. Теперь
  папка загружается рекурсивно, на любую глубину вложенности, с подтверждением и
  прогрессом; «Скачать файл с сервера» для папки так же скачивает каталог целиком.
  Если каталог всё-таки попадёт в загрузку как файл, сообщение будет понятное, а не
  `EISDIR`.

## [0.4.9]

### Добавлено

- После обновления расширения индекс пересобирается сам, если изменился разбор кода:
  больше не нужно помнить про команду «Перестроить индекс» после критических изменений.
- Проблемы показываются по всему проекту, а не только в открытых файлах — иначе после
  перезагрузки окна список пустел. Проверка запускается после индексации и после
  «Перестроить индекс»; управляется настройками `bitrix.diagnostics.projectScan` и
  `bitrix.diagnostics.projectLimit`.

### Исправлено

- «Загрузить файл на сервер» для папки из проводника падало с `EISDIR`: теперь папка
  загружается рекурсивно, с подтверждением и прогрессом.
- Предупреждения о неизвестных переменных больше не срабатывают там, где переменная на
  самом деле есть: параметры стрелочных функций, запись по индексу
  (`$list[$key]['x'] = ...`), переменные из `extract()` и из аннотаций `@var` в
  подключённых файлах. На реальном проекте это убрало почти все такие предупреждения.
- Настройка `bitrix.php.ignoreSymbols` не действовала: список игнорируемых символов
  читался раньше, чем приходили настройки, и оставался пустым.

## [0.4.8]

### Добавлено

- Настройка `bitrix.php.ignoreSymbols` — имена функций и методов, которые не проверять на
  существование (по умолчанию `d` — внешний отладочный хелпер).

### Исправлено

- Импорты вида `use Prefix\{A, B as C};` не разбирались, поэтому классы и родители из них
  считались отсутствующими: отсюда ложные «класс не импортирован» и «метод не найден».
  Теперь разбираются.
- Динамические методы, объявленные в докблоке класса через `@method`, не попадали в
  индекс и считались отсутствующими.
- Ложные предупреждения в вызовах: стрелочная функция `fn(...)` принималась за вызов,
  heredoc/nowdoc разбирались как код, `implode(', ', $a)` считался вызовом с тремя
  аргументами, спред-аргументы проверялись по количеству, лишние аргументы у своих
  функций проверялись, хотя PHP их игнорирует, а необязательные параметры встроенных
  функций считались обязательными.
- Переменные, переданные по ссылке (`preg_match(..., $matches)`), считались
  необъявленными.
- Функции и методы искались с учётом регистра, хотя в PHP он не важен: `showError()` не
  находился у `ShowError()`. Функции, объявленные внутри метода, не индексировались, хотя
  в PHP они глобальные.
- Файлы модулей в корне и `bitrix/activities` не индексировались, как и вложенные
  `vendor/` — их функции и классы считались неизвестными.
- Встроенные описания PHP могли не импортироваться целиком, если в них встречался
  дубликат класса. Дубликаты отсекаются.
- Один и тот же класс в разных файлах (копии компонентов) больше не «съедал» методы:
  переиндексация одного файла не удаляет методы его тёзок, а метод сначала ищется в
  файле самого класса.
- Деструктуризация `[$a, $b] = ...` не считалась объявлением переменных, а `break(2)` и
  `continue(2)` — вызовами функций.
- Не предупреждаем о методах интерфейсов и о цепочках, где тип зависит от строки
  (`GetService('…')->method()`).
- Проверка «необъявленный `$arParams`» отключена: у компонентов параметры приходят из
  шаблона или родителя, ложных срабатываний было больше, чем пользы.

### Обновление

- Нужна переиндексация: изменились разбор импортов, набор индексируемых каталогов и
  встроенные описания PHP.

## [0.4.7]

### Исправлено

- Поиск методов учитывал регистр, хотя в PHP он не важен: `GetId()` не находился у класса
  с `GetID()`, `fetch()` — у класса с `Fetch()`. Теперь регистр не важен.

  объявленный у потомка, считался отсутствующим. Теперь тип сохраняется целиком, а для
  поиска метода берётся потомок.

### Обновление

- Нужна переиндексация: тип из докблока хранится в индексе.

## [0.4.6]

### Исправлено

- Подпись параметра вставала не на месте, если аргумент начинался со строки: в
  `f("a", $x)` подпись первого параметра оказывалась за `"a"`.

- Число наследников и переопределений над объявлением.
- Подписи параметров в вызовах.
- Сворачивание классов, функций, вложенных блоков и `#region`.

### Типы

- Вывод по литералам, `new`, `@var`, `@param`, `@return`, по параметрам функций и методов.
- Массивы объектов: `Foo[]`, `array<Foo>`, `list<Foo>`, `array{KEY: Foo[]}` — в том числе в
  `foreach` и при обращении по индексу.
- Сужение типа после `instanceof` и `assert`.
- Проверка аргументов и возвращаемых значений с учётом иерархии классов, `strict_types` и
  nullable.

### Правки

- Переименование локальных переменных с защитой от опасных случаев.
- Ссылки на файлы в `require` и `include`.
- Форматирование: пробелы в конце строк и перевод строки в конце файла.

## [0.3.24]

### Добавлено

- Аннотации вида `array{KEY: Foo[]}`: тип элемента подсказывается в `foreach` и при
  обращении по индексу, в том числе у свойств. Учитывается вложенность и имя переменной в
  `@var`.
- Тип свойства берётся из `@var` в открытом файле, даже если файла ещё нет в индексе.

### Исправлено

- В `foreach` по ассоциативному массиву тип элемента больше не теряется из-за строковых
  ключей.

## [0.3.23]

### Добавлено

- Ссылки на файлы в `require` и `include` — только для существующего файла.
- Форматирование файла и выделения: убирает пробелы в конце строк и оставляет один
  перевод строки в конце файла. Файлы с heredoc и nowdoc пропускаются, отступы и стиль
  скобок не меняются.

## [0.3.22]

### Добавлено

- Иерархия типов: прямые родители и интерфейсы класса, прямые наследники и реализации.
  Короткая запись `extends Foo` находит нужный класс.

## [0.3.21]

### Добавлено

- Иерархия вызовов: кто вызывает метод и кого вызывает он сам. Для `new Foo()`
  показывается конструктор.

### Исправлено

- Внутри тела метода он теперь определяется корректно: работают типы параметров и поиск
  вызывающего.
- При поиске вызовов код проекта идёт раньше ядра, иначе лимит выбирался ядром и вызовы
  из проекта не находились.

## [0.3.20]

### Добавлено

- Тип элемента массива из PHPDoc: `Foo[]`, `array<Foo>`, `list<Foo>`. Работает в `foreach`,
  при обращении по индексу, в hover и в переходе к типу.
- `@var` и `@param` больше не подхватываются из соседнего метода с тем же именем
  переменной.
- У свойств PHPDoc точнее нативного `array`.

## [0.3.19]

### Добавлено

  открывает список.
- Список не пересчитывается на каждый запрос — кэш на минуту.

## [0.3.18]

### Добавлено

- Переименование локальной переменной и параметра: меняется объявление и все
  использования в файле.
- Отказ там, где замена может сломать код: вхождение в строке или комментарии,
  переменная переменной, имя строкой, суперглобальная, невалидное или занятое имя.
  Классы и методы не переименовываются.

## [0.3.17]

### Добавлено

- Подписи параметров в вызовах функций, методов и конструкторов, в подсказке — тип
  параметра. Работает и для библиотечных классов, и для встроенных функций.
- Не подписываются именованные аргументы, вызовы через переменную и параметры со
  сгенерированными именами.

## [0.3.16]

### Добавлено

- Сужение типа после `instanceof`: внутри блока, после проверки с ранним выходом и после
  `assert`. Видно в hover, в переходе к типу и в подсказках по членам.

## [0.3.15]

### Добавлено

- Переход к типу: у переменной — по присваиванию, параметру или `$this`, у вызова метода —
  по возвращаемому типу, у свойства — по типу из индекса.
- Переход к реализациям: наследники и реализации интерфейса, у метода — переопределения в
  наследниках.

### Исправлено

- Тип параметра выводится и у обычных функций, а не только у методов класса.

## [0.3.14]

### Добавлено

- Проверка типов учитывает иерархию: `new Child()` подходит для параметра `Parent`,
  `self`, `static` и `parent` разрешаются относительно текущего класса.
- Без `strict_types` скалярные приведения допустимы (`'5'` в `int`, `123` в `string`), с
  ним — нет; недопустимое приведение остаётся ошибкой в обоих случаях.
- `null` в параметр без `?` — ошибка, а `?Type` больше не даёт ложного срабатывания.

### Исправлено

- Строковые литералы в `return` не теряются при проверке.
- Строковые и массивные callable принимаются параметром `callable`.

## [0.3.13]

### Добавлено

  `#region` и многострочные комментарии.
