# Changelog

Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), версии — [SemVer](https://semver.org/lang/ru/).
Ведём с текущей версии.

## [0.5.0]

### Добавлено

- Реальный прогресс переноса. Для одного файла — проценты и байты (`10.4 КБ / 250 КБ`)
  из шага передачи ssh2; для каталога — `12 из 340 файлов · 3.4 МБ / 12.1 МБ (28%)`
  с полосой прогресса в уведомлении.
- Настройка `bitrix.ssh.concurrency` (по умолчанию 4, до 16) — сколько файлов
  переносить одновременно при загрузке и скачивании каталога.

### Изменено

- Каталог переносится параллельно, а не строго по одному файлу; проверка конфликтов
  по mtime тоже идёт параллельно. Каталоги на сервере создаются один раз за
  операцию (кэш известных каталогов), а не проверяются `stat`-ом на каждый файл.
  На множестве мелких файлов это убирает основную часть задержки (каждый файл
  раньше стоил 5–8 последовательных round-trip'ов).

### Исправлено

- Статус-бар мигал «сервер не выбран» при каждой загрузке: любая ошибка
  sftp-операции (нет файла, нет прав, отказ rename) считалась обрывом связи —
  соединение закрывалось и поднималось заново, отсюда и мигание, и лишнее
  рукопожатие на каждой операции. Теперь переподключение только при реальном
  обрыве, а закрытую сервером (idle-таймаут) сессию расширение поднимает в фоне,
  показывая `‹сервер›: переподключение…` вместо «сервер не выбран».

## [0.4.11]

### Изменено

- Резервные копии `.bak` больше не создаются — ни на сервере при загрузке, ни
  локально при скачивании. Загрузка по-прежнему идёт через временный файл
  `*.bitrix-assistant-<pid>.tmp`, а перезапись цели выполняется атомарно
  (`posix-rename@openssh.com`), с откатом на `unlink` + `rename` для серверов без
  этого расширения. Паттерны `**/*.bak` остались в `bitrix.ssh.exclude` по
  умолчанию, чтобы старые бэкапы не уезжали на сервер.

## [0.4.10]

### Исправлено

- «Загрузить файл на сервер» из контекстного меню Explorer на папке падало с
  `EISDIR: illegal operation on a directory, read`: путь каталога уходил в SFTP
  `fastPut` как файл. Теперь папка загружается рекурсивно, на любую глубину
  вложенности (с подтверждением и прогрессом, как в дереве сервера), «Скачать файл
  с сервера» на папке — так же рекурсивно скачивает каталог. `SyncService.upload`
  на каталоге даёт внятную ошибку вместо EISDIR.

## [0.4.9]

### Добавлено

- Версия индексатора (`PARSER_VERSION` в `src/indexer/schema.ts`). Если после
  обновления расширения она не совпадает с записанной в индексе, полная
  переиндексация запускается сама — больше не нужно помнить про команду
  «Перестроить индекс» после критических изменений разбора.
- Диагностика по всему проекту после индексации: LSP иначе присылает проблемы только
  для открытых файлов, и после перезагрузки окна список пустеет. Теперь после
  индексации и после «Перестроить индекс» выполняется проектная проверка
  (настройка `bitrix.diagnostics.projectScan`, лимит — `bitrix.diagnostics.projectLimit`).

### Исправлено

- «Загрузить файл на сервер» из контекстного меню Explorer на папке падало с
  `EISDIR: illegal operation on a directory, read`: путь каталога уходил в SFTP
  `fastPut` как файл. Теперь папка загружается рекурсивно (с подтверждением и
  прогрессом, как в дереве сервера), «Скачать файл с сервера» на папке —
  рекурсивно скачивает каталог. `SyncService.upload` на каталоге даёт внятную
  ошибку вместо EISDIR.
- `undefined-variable` срабатывал на объявлениях, которые анализатор не учитывал:
  параметры стрелочных функций (`fn($a) => ...`), запись по индексу
  (`$list[$key]['x'] = ...` — в PHP это создаёт переменную без предупреждения),
  переменные из `extract($array)` и из docblock-аннотаций включённых файлов
  (`/** @var SomeType $var */`). На реальном проекте это убрало почти все такие
  предупреждения.
- Настройка `bitrix.php.ignoreSymbols` не действовала: список игнорируемых символов
  запоминался при создании сервера, то есть до того, как клиент присылал настройки,
  и оставался пустым. Теперь настройки читаются актуальные.

## [0.4.8]

### Исправлено

- Групповые импорты (`use Prefix\{A, B as C};`) не разбирались, поэтому классы и
  родители из них не находились: ложные «класс не импортирован», «метод не найден»,
  неверные типы. Теперь разбираются и в анализаторе, и в индексаторе.
- `@method` в докблоке класса не попадал в индекс, поэтому динамические методы
  считались отсутствующими.
- `fn(...)` принималось за вызов функции (это стрелочная функция PHP).
- Heredoc/nowdoc не маскировались: код и разметка внутри `<<<HTML` разбирались как PHP
  и давали «функция не найдена».
- «Лишние» аргументы проверялись и у пользовательских функций, хотя PHP их игнорирует;
  вызовы со спредом (`f(...$args)`) больше не проверяются по количеству.
- Аргументы вызова делились по запятым внутри строк: `implode(', ', $a)` считался
  вызовом с тремя аргументами.
- Стабы PHP могли не импортироваться целиком: дубликат класса в файле стабов ломал
  INSERT по уникальному ключу и откатывал транзакцию. Дубликаты отсекаются.
- Необязательные параметры встроенных функций без значения по умолчанию считались
  обязательными (`array_keys($a)` → «ожидается аргументов 2–3»).
- Переменные, переданные по ссылке (`preg_match(..., $matches)`), считались
  необъявленными.
- Файлы модулей в корне (`functions.php` и подобные) и `bitrix/activities` не
  индексировались, поэтому их функции и классы считались отсутствующими.
- Проверка необъявленных `$arParams` отключена: у компонентов параметры часто приходят
  из шаблона или родителя, поток ложных срабатываний перекрывал пользу.
- Один и тот же класс в разных файлах (копии компонентов) больше не «съедал» методы:
  раньше переиндексация одного файла удаляла методы одноимённых классов из остальных.
  Поиск метода сначала смотрит в файл самого класса.

- Функции искались с учётом регистра, хотя в PHP он не важен: `showError()`
  не находился у `ShowError()`.
- Функции, объявленные внутри тела метода (`function helper(){}`), не индексировались,
  хотя в PHP они глобальные.
- Вложенные `vendor/` (в модулях и `local/php/src`) не индексировались — хелперы
  пакетов считались неизвестными.
- Аргументы-деструктуризация (`[$a, $b] = ...`) не считались объявлением переменных.
- `break(2)` и `continue(2)` принимались за вызовы функций.
- Метод `$this->…` искался в произвольной копии одноимённого класса: теперь сначала
  в файле самого класса.
- Не предупреждаем о методах интерфейсов и о цепочках с динамической
  диспетчеризацией (`GetService('…')->method()`), где тип зависит от строки.

### Добавлено

- Настройка `bitrix.php.ignoreSymbols` — имена функций/методов, которые не проверять
  на существование (по умолчанию `d` — внешний отладочный хелпер).

### Обновление

- Нужна переиндексация: изменились разбор импортов, индексируемые каталоги и стабы.

## [0.4.7]

### Исправлено

- Поиск методов был регистрозависимым, хотя в PHP регистр в именах методов не важен:
  `GetId()` не находился у класса с `GetID()`, `fetch()` — у класса с `Fetch()`.
  Теперь поиск идёт без учёта регистра.
- Тип из `@var` и `@return` обрезался по первому пробелу, поэтому `@return Base | Child`
  сохранялся как `Base`. Метод, объявленный у потомка, из-за этого считался
  отсутствующим. Теперь union сохраняется целиком, а если в типе пара «родитель и
  потомок», для поиска метода берётся потомок.

### Обновление

- Нужна переиндексация: тип из докблока хранится в индексе.

## [0.4.6]

### Исправлено

- Подпись параметра вставала после аргумента, если аргумент начинался со строки:
  в `f("a", $x)` подпись первого параметра оказывалась за `"a"`. Границы аргументов
  теперь считаются по исходному тексту, структура вызова (скобки, запятые) — по маске.
- У аргумента, который называется так же, как параметр (`$this->id` для `$id`),
  подписи не было. Эвристику «и так понятно» убрал: подпись есть у каждого
  позиционного аргумента.

## [0.4.5]

### Исправлено

- При наборе в большом файле диагностика пересчитывалась целиком на каждый символ
  (около секунды на файле в ~500 строк) и занимала сервер — подсказки ждали в очереди.
  Теперь диагностика запускается после паузы 350 мс; при открытии и сохранении —
  сразу.
- Контекст документа кэшируется по содержимому. Раньше он строился заново на каждый
  вызов в файле (маска и разбор классов), это и давало секунды. На том же файле
  диагностика ускорилась примерно с 1100 до 50 мс, ответ на подсказку при наборе
  занимает единицы миллисекунд.

## [0.4.4]

### Исправлено

- После ведущего `\` предлагались функции: на `\Fo` список заполнялся функциями,
  начинающимися с `Fo`, вместо классов. Теперь имена с `\` и namespace-пути
  обслуживает провайдер классов, функции там не подмешиваются.
- Один и тот же класс из двух копий проекта больше не показывается несколько раз.

### Изменено

- В автодополнении классов справа показывается полное имя класса, серым — модуль.
  Вставка по-прежнему коротким именем с `use`.

## [0.4.3]

- Скрипт сборки больше не перезаписывает стабы минимальным бинарником; пересборка —

## [0.4.2]

### Исправлено

- Тип из `@return` и `@var` искался по короткому имени во всём индексе: если в проекте
  есть два класса с одинаковым именем в разных namespace, выбирался чужой — и на
  цепочке вызовов появлялась ошибка о несуществующем методе. Теперь тип резолвится
  в файле, где объявлен метод, с его `use`-алиасами.
- Поиск класса по короткому имени в выводе типов убран. Глобальные классы

## [0.4.0]

Сводка того, что появилось в LSP после 0.3.5. Подробности — в записях ниже.

### Навигация

- Все ссылки на символ, подсветка вхождений, переход к типу и реализациям.
- Иерархия вызовов и иерархия типов.
- Число наследников и переопределений над объявлением.
- Подписи параметров в вызовах.
- Сворачивание классов, функций, вложенных блоков и `#region`.

### Типы

- Вывод по литералам, `new`, `@var`, `@param`, `@return`, параметрам функций и методов.
- Массивы объектов: `Foo[]`, `array<Foo>`, `list<Foo>`, `array{KEY: Foo[]}`,
  включая `foreach` и обращение по индексу.
- Сужение типа после `instanceof` и `assert`.
- Проверка аргументов и возвращаемых значений с учётом иерархии классов,
  `strict_types` и nullable.

### Правки

- Переименование локальных переменных с защитой от опасных случаев.
- Ссылки на файлы в `require` и `include`.
- Форматирование: пробелы в конце строк и перевод строки в конце файла.

## [0.3.24]

### Добавлено

- Shape-аннотации `array{KEY: Foo[]}`: тип элемента выводится в `foreach` и при
  обращении по индексу, в том числе для свойств. Учитывается вложенность,
  описание после типа и имя переменной в `@var`.
- Тип свойства берётся из `@var` в самом документе, если файла ещё нет в индексе.

### Исправлено

- Источник `foreach` читается из исходного текста, а не из маски: ключи-строки
  больше не превращаются в пробелы, вывод типа элемента работает для ассоциативных
  массивов.

## [0.3.23]

### Добавлено

- Ссылки на файлы в `require` и `include`; ссылка появляется только для
  существующего файла.
- Форматирование документа и выделения: убирает пробелы в конце строк, где
  заканчивается код, и оставляет один перевод строки в конце файла. Файлы с
  heredoc и nowdoc пропускаются, отступы и стиль скобок не меняются.

## [0.3.22]

### Добавлено

- Иерархия типов: прямые родители и интерфейсы класса, прямые наследники и
  реализации. Имена резолвятся в namespace объявления, поэтому короткая запись
  `extends Foo` находит нужный класс.

## [0.3.21]

### Добавлено

- Иерархия вызовов: кто вызывает метод и кого вызывает он сам. Входящие вызовы
  ищутся по тексту проиндексированных файлов, исходящие — разбором тела.
  Для `new Foo()` показывается конструктор.

### Исправлено

- Диапазон метода теперь включает тело, а не только сигнатуру. Из-за этого внутри
  тела не определялся текущий метод: не выводились типы параметров методов и
  не определялся вызывающий.
- При поиске вызовов файлы проекта идут раньше файлов ядра, иначе лимит выбирался
  ядром и вызовы из кода проекта не находились.

## [0.3.20]

### Добавлено

- Тип элемента массива из PHPDoc: `Foo[]`, `array<Foo>`, `list<Foo>`. Работает
  в `foreach`, при обращении по индексу, в hover и в переходе к типу.
- Поиск `@var` и `@param` ограничен текущей функцией: аннотация из соседнего метода
  с тем же именем переменной больше не подхватывается.
- Для свойств PHPDoc точнее колонки в индексе: `@var Foo[]` важнее нативного `array`.

## [0.3.19]

### Добавлено

- Над классом показывается число наследников, над методом — число переопределений.
  Клик открывает список через стандартную команду VS Code, отдельных команд
  в расширении не нужно.
- Кэш обхода иерархии на 60 секунд, чтобы список не пересчитывался на каждый запрос.

## [0.3.18]

### Добавлено

- Переименование локальной переменной и параметра: меняется и объявление, и все
  использования в файле.
- Отказы там, где замена может сломать код: вхождение в строке или комментарии,
  переменная переменной, имя строкой (`compact`), суперглобальная, невалидное
  или занятое имя. Классы и методы не переименовываются.

## [0.3.17]

### Добавлено

- Подписи параметров в вызовах функций, методов и конструкторов. В подсказке —
  тип параметра. Работает по индексу, поэтому подписи есть и у библиотечных
  классов, и у встроенных функций.
- Не подписываются именованные аргументы, вызовы через переменную и параметры

## [0.3.16]

### Добавлено

- Сужение типа после `instanceof`: внутри блока, после проверки с ранним выходом
  и после `assert`. Видно в hover и в переходе к типу, значит и в подсказках
  по членам.

## [0.3.15]

### Добавлено

- Переход к типу: для переменной тип выводится по присваиванию, параметру или
  `$this`; для вызова метода — по возвращаемому типу, для `static` и `self` —
  по типу получателя; для свойства — по типу из индекса.
- Переход к реализациям: наследники и реализации интерфейса, для метода —
  переопределения в наследниках.

### Исправлено

- Тип параметра выводится и у обычных функций, а не только у методов класса.

## [0.3.14]

### Добавлено

- Проверка типов учитывает иерархию: `new Child()` подходит для параметра `Parent`,
  `self`, `static` и `parent` разрешаются относительно текущего класса.
- Тип из сигнатуры резолвится в namespace объявляющего файла с его `use`-алиасами.
- Без `strict_types` скалярные приведения допустимы (`'5'` в `int`, `123` в `string`),
  со `strict_types` — нет; недопустимое приведение остаётся ошибкой в обоих случаях.
- `null` в non-nullable параметр — ошибка; `?Type` больше не даёт ложного срабатывания.

### Исправлено

- Значение `return` читается из исходного текста, поэтому строковые литералы
  не теряются при проверке.
- Строковые и массивные callable принимаются параметром `callable`.

## [0.3.13]

### Добавлено

- Сворачивание кода: тела классов, интерфейсов, трейтов и функций, вложенные блоки,
  `#region` и многострочные комментарии. Строки и heredoc при разборе маскируются.
  Для скобки на отдельной строке диапазон начинается со строки объявления.

## [0.3.12]

### Добавлено

- Все ссылки на символ по проиндексированным файлам, объявление подсвечивается
  именем, а не всей строкой.
- Подсветка вхождений в текущем файле.

## [0.3.11]

### Добавлено

- Индексирование Composer-зависимостей: подсказки, hover и переходы работают
  по классам библиотек. Отключается настройкой.

## [0.3.10]

### Исправлено

- Гонка между изменением текста и запросом подсказок: сервер успевал разобрать
  прошлую версию и отдавал элементы по чужому префиксу. Клиент отправляет запрос
  после синхронизации, сервер не отвечает на позицию за концом документа.
- `_` добавлен в триггеры, поэтому список после подчёркивания запрашивается заново.
- Несуществующий префикс больше не оставляет пустой список: сервер отдаёт ближайший
  подходящий вариант с подстроенной фильтрацией.

## [0.3.9]

### Добавлено

- Стабы встроенного PHP в индексе: сигнатуры функций и классов, методы, свойства,
  константы. Подсказки и переходы по stdlib не зависят от встроенной поддержки PHP
  в редакторе. Импорт включается настройкой.

## [0.3.8]

### Исправлено

- Внутри `<script>` подсказки и переходы обслуживает только JS-анализатор,
  PHP-функции в JS-вызовы больше не попадают. PHP-блоки внутри `<script>`
  по-прежнему обслуживаются PHP.
- Вызов private/protected метода снаружи класса виден в Problems. Изнутри класса
  и из наследника для protected — без предупреждения; `__call` и `@method` не трогаем.
- JS: ES6-классы с `@memberof` попадают в короткие имена вместе с методами.
  Причин было две: регистр тега и докблок, который не находился после `export`.

## [0.3.7]

### Исправлено

- Неизвестные методы и функции всегда видны в Problems, остальные семантические
  проверки остались за настройкой.
- Отключены встроенные подсказки и валидация PHP в редакторе: они подмешивали
  суперглобальные переменные и функции из справки, а также дублировали диагностику.
- JS: вывод типа для `new A.B.C()` сохраняет весь путь, а не первый сегмент,
  поэтому после переменной показываются члены класса, а не все глобальные объекты.

## [0.3.6]

### Исправлено

- Hover после `->` и `::` больше не показывает глобальную функцию с тем же именем.
- Неизвестный метод известного класса виден в Problems; не срабатывает для
  `__call` и встроенных классов.
- Опечатка не-ASCII символами (другая раскладка) тоже ловится.
- Для PHP отключены подсказки «по словам»: они давали приватные методы и имена
  из других файлов.

## [0.3.5]

### Исправлено

- Hover и переход в PHP-файлах больше не обслуживаются JS-анализатором: он находил
  чужие методы с тем же именем. JS подключается только внутри `<script>`.
- Подсказки после `->` и `::` не фильтруются по префиксу на сервере: фильтрует
  редактор, иначе в список попадали слова из открытых файлов.
- В списке членов нет магических методов и приватных членов при доступе снаружи.

## [0.3.4]

### Исправлено

- Hover по классу показывает конструктор: для индексируемых классов — из иерархии,
  для наследников встроенных — из каталога PHP.

## [0.3.3]

### Исправлено

- Подсказка сигнатуры для `new Foo(...)`, в том числе для наследников встроенных
  классов.
- Вывод типа для выражения в скобках: цепочка после `(new Foo(...))` больше
  не теряет получателя.
- Hover для встроенных классов PHP, которых нет в индексе.
- Исправлена e2e-проверка вывода типа из возвращаемого значения.

## [0.3.2]

### Добавлено

- Уведомление с прогрессом при загрузке на сервер, отметка в статус-баре при успехе
  и ошибке. При автозагрузке по сохранению — только спиннер.
- Колонка «Тип» в таблице параметров; тип берётся из сигнатуры, при её отсутствии —
  из `@param`.
- Подсветка сигнатуры в hover и в карточке автодополнения.
- Типы известных глобальных переменных, включая легаси-форму через `$GLOBALS`.
- Порядок членов в подсказках: свои, унаследованные, магические.
- Команда сравнения с сервером и терминал на сервере.
- Версия PHP привязана к папке проекта и хранится в состоянии расширения,
  а не в общих настройках.
- Пути к PHP по версиям поддерживают `~` и переменные окружения.
- Проверка доступности выбранной версии PHP при старте и при смене настройки.

### Исправлено

- Автодополнение классов с ведущим `\`: диапазон замены согласован с фильтрацией.
- Подсказки для классов из вложенных namespace не отсекаются фильтром.
- Имена трейтов, `extends` и `implements` резолвятся через `use`-импорты.
- Конфликт версий при загрузке решается по содержимому файла.
- Самовосстановление индекса при повреждённой базе.
- SSH: пароль запрашивается один раз и сохраняется, поддержан `keyboard-interactive`.

### Изменено

- В пакет встраивается PHP 8.4; остальные версии ставятся на компьютер или
  указываются в настройках.
- Схема индекса 16, требуется переиндексация.
