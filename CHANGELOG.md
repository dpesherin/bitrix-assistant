# Changelog

Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), версии — [SemVer](https://semver.org/lang/ru/).
Ведём с текущей версии.

## [0.3.16]

### Добавлено

- **Flow-narrowing для `instanceof`**: тип переменной сужается внутри блока
  `if ($x instanceof Foo) { … }`, после guard-проверки `if (!$x instanceof Foo) { return; }`
  и после `assert($x instanceof Foo);`. Работает в hover (показывает конкретный класс
  вместо `mixed`/интерфейса) и в «Go to Type Definition», а значит и в подсказках
  по членам суженного типа.
- Сужение учитывает `use`-алиасы документа и проверяет, что класс есть в индексе,
  поэтому одноимённые классы из других namespace не подставляются.

## [0.3.15]

### Добавлено

- **Переход к типу** (`textDocument/typeDefinition`, `Ctrl+F12` / `Go to Type Definition`):
  для переменной тип выводится по присваиванию, параметру функции или `$this`,
  для вызова метода — по объявленному `return type` (у `static`/`self` — по типу
  получателя, то есть работают fluent-цепочки), для свойства — по типу из индекса.
- **Переход к реализациям** (`textDocument/implementation`): от интерфейса или класса —
  все наследники и реализации (транзитивно, `Repository::descendantsOf()`), от метода —
  его переопределения в наследниках (`Repository::methodImplementations()`).

### Исправлено

- Тип параметра теперь выводится и у **обычных функций**, а не только у методов класса
  (`PhpDocumentContext::functionParamsAt()`): hover/тип переменной-параметра и навигация
  работают в функциях и в файлах без класса.

## [0.3.14]

### Добавлено

- **Иерархия классов в проверке типов**: аргумент `new Child()` подходит для параметра
  `Parent` или интерфейса (обход `extends`/`implements`/трейтов по индексу,
  `Repository::classIsA()`); `self`, `static`, `parent` разрешаются относительно текущего
  класса. Тип из сигнатуры резолвится в namespace **объявляющего** файла с его
  `use`-алиасами, а не вызывающего — из-за этого раньше `Bitrix\Main\Error`
  не подходил под параметр `Error` из `Bitrix\Main`.
- **`declare(strict_types=1)`**: без него PHP приводит скаляры (`'5'` → `int`,
  `123` → `string`), и ошибкой это больше не считается; со `strict_types` в сообщении
  указана причина. Приведение, недопустимое и в coercive-режиме (`'abc'` → `int`),
  остаётся ошибкой всегда.
- **Nullability**: `null` в non-nullable параметр — ошибка; `?Type`/`Type|null`
  больше не даёт ложного срабатывания.

### Исправлено

- Значение `return` читается из исходного текста, а не из маскированного: строковые
  литералы не терялись, и `return '5';` в `function f(): int` проверяется корректно.
- Строковые и массивные callable (`'trim'`, `[$this, 'method']`) принимаются
  параметром `callable` — ложных срабатываний на `array_map`/`array_filter` нет.

## [0.3.13]

### Добавлено

- **Сворачивание кода** (`textDocument/foldingRange`) для PHP и JS-вставок: тела
  классов, интерфейсов, трейтов и функций, вложенные блоки (`if`, `try`, `switch`),
  `// #region` / `#region` … `#endregion` и многострочные `/* … */`.
  Строки, комментарии и heredoc/nowdoc при разборе маскируются, поэтому скобки внутри
  текста не рвут диапазоны. Для стиля с `{` на отдельной строке сворачивание начинается
  с строки объявления.

## [0.3.12]

### Добавлено

- **Find All References** для PHP (`textDocument/references`): сервер ищет вхождения
  метода, свойства, класса или функции по проиндексированным файлам (список берётся
  из `file_hashes`, лимиты 4000 файлов / 400 результатов) и отдаёт точные диапазоны.
  Объявление добавляется с подсветкой самого имени, а не всей строки.
- **Подсветка вхождений** в текущем файле (`textDocument/documentHighlight`) —
  `Shift+F12`/`Ctrl+F7`-подобное поведение для PHP без ожидания переиндексации.

## [0.3.11]

### Добавлено

- **Индексирование `vendor/`** (и `local/vendor/`): PHP-файлы Composer-зависимостей
  попадают в индекс, поэтому работают подсказки, hover, сигнатуры и переходы по
  классам библиотек. Настройка `bitrix.index.vendor` (по умолчанию включена).

## [0.3.10]

### Исправлено

- Гонка между `textDocument/didChange` и запросом подсказок на trigger-символе:
  сервер успевал разобрать **старый** текст (`$a = s` вместо `$a = str_`) и отдавал
  чужие элементы — например константы `SALE_*` по префиксу `s`. Теперь клиент
  отправляет запрос после синхронизации текста (middleware с задержкой), а сервер
  не отвечает, если запрошенная позиция лежит за концом известного ему документа.
- `_` добавлен в triggerCharacters, поэтому после подчёркивания список запрашивается
  заново, а не фильтруется по уже показанным элементам.
- `str_con_` (нет такой функции) больше не оставляет пустой/залипший список:
  сервер отдаёт ближайший валидный префикс (`str_contains`) с подстроенным
  `filterText` и диапазоном на весь ввод.

## [0.3.9]

### Добавлено

- **Стабы PHP в индексе**: `scripts/build-php-stubs.php` выгружает из рантайма PHP 8.4
  сигнатуры 833 встроенных функций и 169 классов (методы, свойства, константы,
  наследование) в `server/data/php-stubs.json`; индексатор импортирует их при синхронизации
  (`bitrix.index.phpStubs`, по умолчанию включено). Подсказки, hover, сигнатуры и переходы
  по stdlib больше не зависят от встроенной поддержки PHP в VS Code (она отключена).

## [0.3.8]

### Исправлено

- Внутри `<script>` в PHP-шаблоне подсказки, hover, переходы и сигнатуры обслуживает
  только JS-анализатор: раньше при вводе параметров JS-вызова (`new BX.Main.Popup({ … })`)
  в список попадали функции PHP. При этом PHP-блоки внутри `<script>` (`<?= … ?>`,
  `<?php … ?>`) по-прежнему обслуживаются PHP-анализатором.
- Вызов `private`/`protected` метода снаружи класса теперь виден в Problems
  (`bitrix.php.method-visibility`, severity Error): работает и в шаблонах
  (`<?= (new \Testing\Test())->test() ?>`), и в обычном коде. Изнутри своего класса
  и из наследника для `protected` — без предупреждения; трейты, `@method` и методы
  с `__call` не трогаем.
- JS-индекс: ES6-классы ядра (`export class Popup` с `@memberof BX.Main`) теперь
  попадают в ES5-имена (`BX.Main.Popup`) вместе с методами и полями. Причин было две:
  JSDoc-теги искались с учётом регистра (`@memberOf`), а докблок не находился, если
  между `*/` и `class` стоял `export`/`abstract`. После переиндексации у `BX.Main.Popup`
  появляются `show`, `close`, `setContent` и остальные члены, а не только `Button`.

## [0.3.7]

### Исправлено

- Неизвестные методы и функции теперь всегда видны в Problems (`bitrix.php.unknown-method`,
  `bitrix.php.unknown-function`): раньше проверка сидела внутри `bitrix.php.semantic`
  (по умолчанию выключена). Остальные семантические проверки остались за настройкой.
- Отключены встроенные подсказки и валидация PHP от VS Code (`php.suggest.basic`,
  `php.validate.enable`): именно они подмешивали в список после `->` superglobals
  (`$_GET`, `$_COOKIE`) и все функции php.net, а также дублировали диагностику.
- JS: вывод типа для `const x = new BX.Main.Popup(...)`. Раньше брался только первый
  сегмент (`BX`), из-за чего после `x.` показывались все 652 глобальные BX-объекта
  вместо членов класса. Теперь путь по сегментам сохраняется.

## [0.3.6]

### Исправлено

- Hover после `->`/`::` больше не подставляет глобальную функцию: `$obj->in_array()`
  не показывает карточку встроенной `in_array()`.
- Неизвестный метод у известного класса теперь виден в Problems:
  «Метод `foo()` не найден в классе `X`» (`bitrix.php.unknown-method`). Не срабатывает
  для классов с `__call`/`__callStatic` и для встроенных классов PHP.
- Опечатка в имени метода не-ASCII символами (русская раскладка, `testЕЕЕ`) тоже
  ловится как неизвестный метод.
- Для PHP отключены «слова как подсказки» (`[php].editor.wordBasedSuggestions: off`):
  именно они давали в списке `$var->` приватные методы, чужие функции из других
  классов и имена из всех открытых файлов.

## [0.3.5]

### Исправлено

- Hover и переход по определению в PHP-файлах больше не обслуживаются JS-анализатором:
  раньше JS искал по имени члена и находил чужие методы (`time` из `bitrix/js/...`)
  — отсюда посторонние карточки с параметрами, которых у класса нет. JS теперь
  подключается только для JS-кода (внутри `<script>`).
- Автодополнение после `->`/`::` больше не фильтруется по префиксу на сервере:
  при отсутствии совпадений VS Code добавлял «слова» из всех открытых файлов
  («огромное количество функций»). Фильтрацию делает редактор по `filterText`.
  Для PHP-файлов `editor.wordBasedSuggestions` по умолчанию ограничен текущим
  документом.
- В списке членов после `->`/`::` больше нет магических методов (`__construct`)
  и приватных/защищённых членов при доступе снаружи класса.

## [0.3.4]

### Исправлено

- Hover по классу показывает конструктор: для индексируемых классов — из
  иерархии (`StatusChanged` → `__construct(array $values = [])` от `AbstractModel`),
  для наследников встроенных — из каталога PHP
  (`NoEntityIdProvidedException` → `__construct(string $message = "", int $code = 0, ?\Throwable $previous = null)`).

## [0.3.3]

### Исправлено

- Подсказка сигнатуры конструктора для `new Foo(...)`: раньше её не было совсем —
  подсказки работали только для `->`/`::`. Для классов, наследующих встроенные
  (например `class X extends \Exception`), параметры берутся из каталога
  встроенных классов PHP: `string $message = "", int $code = 0, ?\Throwable $previous = null`.
- Вывод типа для выражения в скобках: `(new StatusChanged([...]))->fillNillable()`
  больше не теряет получателя — hover, definition и автодополнение по методам
  цепочки работают.
- Hover для встроенных классов PHP (`\DateTimeImmutable`, `\ArrayObject`,
  `\stdClass` и др.): показывается конструктор и описание, хотя исходников нет
  в индексе.
- E2E-проверка вывода типа из возвращаемого типа метода: сверка шла с разметкой
  hover, из-за чего тест падал всегда. Добавлена проверка сигнатуры `new`.

## [0.3.2]

### Добавлено

- Обратная связь при загрузке на сервер: уведомление с прогрессом, зелёная галочка
  `$(check)` в статус-баре при успехе и красный крестик `$(error)` при ошибке.
  При автозагрузке по сохранению — только спиннер, без уведомлений.
- Колонка «Тип» в таблице параметров показывается всегда; тип берётся из сигнатуры,
  при её отсутствии — из `@param`.
- Подсветка сигнатуры в hover и карточке автодополнения: ключевые слова, классы,
  методы, переменные и значения теми же цветами, что и остальной hover.
- Горизонтальные разделители между блоками карточки; «Определение» — мелким
  приглушённым шрифтом внизу.
- Отступы внутри ячеек таблицы параметров и центрирование колонок «Тип»
  и «По умолчанию».
- Типы известных глобальных переменных: `$APPLICATION` → `CMain`, `$USER` → `CUser`,
  `$DB` → `CDatabase`, включая легаси-форму `$GLOBALS['APPLICATION']->`.
- Порядок членов класса в подсказках: свои → унаследованные → магические,
  внутри группы по алфавиту.
- Команда «Сравнить с сервером»: diff локального и серверного файла, при совпадении
  содержимого — статус вместо пустого diff.
- Команда «Терминал на сервере»: интерактивный shell по сохранённому SSH-профилю.
- Версия PHP привязана к папке проекта и хранится в состоянии расширения
  (`workspaceState`), а не в `settings.json`: у каждого проекта в мульти-рут workspace
  своя запись, LSP и проверка синтаксиса читают её. Настройки `bitrix.php.version` /
  `bitrix.php.paths` остались как значения по умолчанию.
- Пути к PHP по версиям (`{ "8.3": "/opt/homebrew/opt/php@8.3/bin/php" }`) вводятся
  строкой, без выбора файла; поддерживаются `~` и `${env:VAR}`.
- Команды «указать путь к PHP для версии» (`bitrix.php.setPath`) и «проверить PHP,
  выбранный для проекта» (`bitrix.php.checkRuntime`).
- Проверка доступности выбранной версии PHP при старте и при смене настройки:
  если версии нет ни во встроенном рантайме, ни в `bitrix.php.paths`/PATH, расширение
  предлагает скачать сборку или указать путь, вместо тихой подстановки другой версии.

### Исправлено

- Автодополнение классов: `filterText` и диапазон замены согласованы с фильтрацией
  VS Code, поэтому `\CFile`, `\CCrmDeal` и подобные снова показываются.
- Подсказки для `\Bitrix\Main\…` больше не отсекаются фильтром глобальных классов.
- Имена трейтов, `extends` и `implements` резолвятся через `use`-импорты файла —
  методы трейтов видны в подсказках.
- Конфликт версий при загрузке решается по содержимому (размер + sha256): если файл
  на сервере новее, но содержимое совпадает, загрузка пропускается без вопроса.
- Самовосстановление индекса при `database disk image is malformed`; при атомарной
  перестройке не остаются `-wal`/`-shm` от прежней базы.
- SSH: при неудачной аутентификации пароль запрашивается один раз и сохраняется,
  поддержан `keyboard-interactive`; удалённый профиль не «воскресает» без пароля.
- Все команды, настройки и сообщения используют имя «Bitrix Assistant».

### Инфраструктура

- Публикация в Marketplace по одной платформе за прогон: массовый прогон Marketplace
  склеивает в один пакет. Описание и команды — `docs/DEVELOPMENT.md`.

### Изменено

- В пакет встраивается PHP 8.4 (static-php-cli, сборка CI): остальные версии PHP
  ставятся на компьютер или в `bitrix.php.paths`; `auto` — определение по ПК.
- `bitrix.php.lintBinary` остаётся как общий путь, для версий появился `bitrix.php.paths`.
- Схема индекса 16 (требуется переиндексация при обновлении).
