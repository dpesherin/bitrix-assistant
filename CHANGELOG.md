# Changelog

Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), версии — [SemVer](https://semver.org/lang/ru/).
Ведём с текущей версии.

## [0.3.6]

### Исправлено

- Hover после `->`/`::` больше не подставляет глобальную функцию: `$obj->in_array()`
  не показывает карточку встроенной `in_array()`.
- Неизвестный метод у известного класса теперь виден в Problems:
  «Метод `foo()` не найден в классе `X`» (`bitrix.php.unknown-method`). Не срабатывает
  для классов с `__call`/`__callStatic` и для встроенных классов PHP.
- Опечатка в имени метода не-ASCII символами (русская раскладка, `testЕЕЕ`) тоже
  ловится как неизвестный метод.
- Для PHP отключены «слова как подсказки» (`[php].editor.wordBasedSuggestions: off`):
  именно они давали в списке `$var->` приватные методы, чужие функции из других
  классов и имена из всех открытых файлов.

## [0.3.5]

### Исправлено

- Hover и переход по определению в PHP-файлах больше не обслуживаются JS-анализатором:
  раньше JS искал по имени члена и находил чужие методы (`time` из `bitrix/js/...`)
  — отсюда посторонние карточки с параметрами, которых у класса нет. JS теперь
  подключается только для JS-кода (внутри `<script>`).
- Автодополнение после `->`/`::` больше не фильтруется по префиксу на сервере:
  при отсутствии совпадений VS Code добавлял «слова» из всех открытых файлов
  («огромное количество функций»). Фильтрацию делает редактор по `filterText`.
  Для PHP-файлов `editor.wordBasedSuggestions` по умолчанию ограничен текущим
  документом.
- В списке членов после `->`/`::` больше нет магических методов (`__construct`)
  и приватных/защищённых членов при доступе снаружи класса.

## [0.3.4]

### Исправлено

- Hover по классу показывает конструктор: для индексируемых классов — из
  иерархии (`StatusChanged` → `__construct(array $values = [])` от `AbstractModel`),
  для наследников встроенных — из каталога PHP
  (`NoEntityIdProvidedException` → `__construct(string $message = "", int $code = 0, ?\Throwable $previous = null)`).

## [0.3.3]

### Исправлено

- Подсказка сигнатуры конструктора для `new Foo(...)`: раньше её не было совсем —
  подсказки работали только для `->`/`::`. Для классов, наследующих встроенные
  (например `class X extends \Exception`), параметры берутся из каталога
  встроенных классов PHP: `string $message = "", int $code = 0, ?\Throwable $previous = null`.
- Вывод типа для выражения в скобках: `(new StatusChanged([...]))->fillNillable()`
  больше не теряет получателя — hover, definition и автодополнение по методам
  цепочки работают.
- Hover для встроенных классов PHP (`\DateTimeImmutable`, `\ArrayObject`,
  `\stdClass` и др.): показывается конструктор и описание, хотя исходников нет
  в индексе.
- E2E-проверка вывода типа из возвращаемого типа метода: сверка шла с разметкой
  hover, из-за чего тест падал всегда. Добавлена проверка сигнатуры `new`.

## [0.3.2]

### Добавлено

- Обратная связь при загрузке на сервер: уведомление с прогрессом, зелёная галочка
  `$(check)` в статус-баре при успехе и красный крестик `$(error)` при ошибке.
  При автозагрузке по сохранению — только спиннер, без уведомлений.
- Колонка «Тип» в таблице параметров показывается всегда; тип берётся из сигнатуры,
  при её отсутствии — из `@param`.
- Подсветка сигнатуры в hover и карточке автодополнения: ключевые слова, классы,
  методы, переменные и значения теми же цветами, что и остальной hover.
- Горизонтальные разделители между блоками карточки; «Определение» — мелким
  приглушённым шрифтом внизу.
- Отступы внутри ячеек таблицы параметров и центрирование колонок «Тип»
  и «По умолчанию».
- Типы известных глобальных переменных: `$APPLICATION` → `CMain`, `$USER` → `CUser`,
  `$DB` → `CDatabase`, включая легаси-форму `$GLOBALS['APPLICATION']->`.
- Порядок членов класса в подсказках: свои → унаследованные → магические,
  внутри группы по алфавиту.
- Команда «Сравнить с сервером»: diff локального и серверного файла, при совпадении
  содержимого — статус вместо пустого diff.
- Команда «Терминал на сервере»: интерактивный shell по сохранённому SSH-профилю.
- Версия PHP привязана к папке проекта и хранится в состоянии расширения
  (`workspaceState`), а не в `settings.json`: у каждого проекта в мульти-рут workspace
  своя запись, LSP и проверка синтаксиса читают её. Настройки `bitrix.php.version` /
  `bitrix.php.paths` остались как значения по умолчанию.
- Пути к PHP по версиям (`{ "8.3": "/opt/homebrew/opt/php@8.3/bin/php" }`) вводятся
  строкой, без выбора файла; поддерживаются `~` и `${env:VAR}`.
- Команды «указать путь к PHP для версии» (`bitrix.php.setPath`) и «проверить PHP,
  выбранный для проекта» (`bitrix.php.checkRuntime`).
- Проверка доступности выбранной версии PHP при старте и при смене настройки:
  если версии нет ни во встроенном рантайме, ни в `bitrix.php.paths`/PATH, расширение
  предлагает скачать сборку или указать путь, вместо тихой подстановки другой версии.

### Исправлено

- Автодополнение классов: `filterText` и диапазон замены согласованы с фильтрацией
  VS Code, поэтому `\CFile`, `\CCrmDeal` и подобные снова показываются.
- Подсказки для `\Bitrix\Main\…` больше не отсекаются фильтром глобальных классов.
- Имена трейтов, `extends` и `implements` резолвятся через `use`-импорты файла —
  методы трейтов видны в подсказках.
- Конфликт версий при загрузке решается по содержимому (размер + sha256): если файл
  на сервере новее, но содержимое совпадает, загрузка пропускается без вопроса.
- Самовосстановление индекса при `database disk image is malformed`; при атомарной
  перестройке не остаются `-wal`/`-shm` от прежней базы.
- SSH: при неудачной аутентификации пароль запрашивается один раз и сохраняется,
  поддержан `keyboard-interactive`; удалённый профиль не «воскресает» без пароля.
- Все команды, настройки и сообщения используют имя «Bitrix Assistant».

### Инфраструктура

- Публикация в Marketplace по одной платформе за прогон: массовый прогон Marketplace
  склеивает в один пакет. Описание и команды — `docs/DEVELOPMENT.md`.

### Изменено

- В пакет встраивается PHP 8.4 (static-php-cli, сборка CI): остальные версии PHP
  ставятся на компьютер или в `bitrix.php.paths`; `auto` — определение по ПК.
- `bitrix.php.lintBinary` остаётся как общий путь, для версий появился `bitrix.php.paths`.
- Схема индекса 16 (требуется переиндексация при обновлении).
